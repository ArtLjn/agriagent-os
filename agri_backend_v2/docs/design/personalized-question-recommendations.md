# 首页个性化问题推荐

## 用户行为

Playground 空会话将固定调试卡片替换为“猜你想问”。每批最多六条，展示“结合你的偏好”或“探索话题”，支持换一批、加载状态和失败重试。点击只填入并聚焦输入框，用户可以修改后发送，不会立即执行工具。换一批携带最近最多 18 条问题，服务端去除重复问法中的空白和标点差异，提示词进一步要求避免近义重复。

每条推荐都是用户向 AI 发出的完整快捷请求，由 AI 回答。个性化记忆决定用户可能想问的话题，例如喜欢策略游戏时推荐“帮我推荐几款策略游戏，并比较玩法”，偏爱清淡饮食时推荐“给我推荐三道清淡家常菜，附上简单做法”；不能生成“你最喜欢哪款游戏？”“你今天想吃什么？”这类等待用户回答的问题，也不将助手昵称、称呼或问候当作任务。

## 画像来源与生成

复用现有个人设置和已生效长期记忆，包括用户明确保存的偏好，以及自动学习并通过既有生效流程的记忆。推荐本身不扫描原始聊天、不创建或升级记忆。模型结合已保存兴趣、通用对话能力与实际 SkillRegistry 的只读能力生成问题，不再维护固定问题数组。当前没有实时农场、天气或账单数据，因此不能在问题中编造病害、降雨、欠款或待办。

只使用当前用户的全局记忆及当前可信 farm_uid 的农场记忆；候选、删除、过期、其他农场和凭据内容不进入推荐。沿用 use_saved_memories 开关。没有可用偏好或关闭记忆时，让模型生成探索话题并如实标注；存储失败则返回错误，不冒充“没有画像”。优先按更新时间、同时间再按明确来源选择最多八条记忆、4000 字符，保留适用条件；不把助手昵称、身份称谓或单次临时任务当作兴趣。

每条模型输出必须引用现有只读能力或内置 general_conversation 通用对话能力，若附带记忆引用则只能使用本次提供的 ID；服务端验证格式、长度、去重和引用。原始记忆及其 ID 不返回前端。生成不传 tools，不触发业务动作。自然语言相关性和近义多样性仍依赖模型，需持续做实际样本验收。

发问方向由提示词中的角色约束、正反例和生成前自检共同引导。生成器与输出验证共用 USER_REQUEST_PREFIXES：要求推荐以“帮我”“给我”“教我”“我想了解”等用户请求开头，不符合格式的候选被过滤，整批无有效项时返回 recommendations_empty 并允许重试。该限制只约束生成的推荐，不限制用户手动输入；不增加额外模型调用。自然语言含义仍依赖模型，前缀校验不能替代语义验收。提示词和前缀都进入缓存键，更新后不会命中旧批次；运行中的模板缓存需通过既有 Prompt 重载或重启 Agent 更新。

生活兴趣（如游戏、饮食、学习）可以由通用对话直接承接，不要求匹配农业工具。提示词要求有适用兴趣时至少一半推荐围绕记忆展开，服务端把带有效记忆引用的结果排在前面；比例及语义相关性由模型决定，不伪造记忆依据。较新的自动学习记忆不会被八条旧的明确记忆长期挤出候选。仍不输出记忆原文与 ID，不调用工具；通用对话不能承诺实时事实。

## 接口与边界

- `POST /api/v2/me/question-recommendations`：body 为 `{ "exclude": [] }`，禁止额外字段及用户/农场身份覆盖，使用 AGENT_INVOKE 权限。前端通过 `/api/agent/me/question-recommendations` 代理访问。
- 响应 `{items:[{id,question,basis}],mode}`，basis 为 memory/explore，mode 为 personalized/explore；不返回模型工具名。HTTP 设置 `Cache-Control: no-store`。
- 沿用 personalization API 的认证与错误处理；新 `application/question_recommendations.py` 由该 API 调用，独立负责画像选择、生成、输出验证和进程内缓存，不把模型编排塞进路由或记忆持久化模块。
- 新 `prompts/question_recommendations.md` 由生成器通过既有模板加载器读取，可随 Prompt 管理重载；模型提供方复用现有配置。模板内容也进入缓存键。
- 前端 `api/questionRecommendations.ts` 隔离新增协议与模拟用户令牌，避免继续扩大已有大型 agent.ts。QuickPrompts 独立加载和展示，父页面只接收选中的问题。

## 缓存与故障

每批生成/读取最多 20 秒，每进程最多四个同时处理的推荐请求；模型输出预算 1600 tokens。进程内缓存生成结果五分钟，最多 128 项，按最近使用淘汰；缓存不跨进程共享。缓存键包含 JWT 签发域、用户、农场、画像版本与生效内容、北京时间日期、能力目录、提示词和排除列表。缓存读取不延长有效期。

每次请求读取当前画像；返回前再次确认版本及可见内容，生成中删除或关闭记忆将返回 recommendations_context_changed（409）。无可用模型结果返回 recommendations_empty（503），提供方故障或超时返回 recommendations_unavailable（503）。错误日志记录错误类型、总耗时、超时预算以及失败阶段（load_profile / prepare_context / wait_generation_slot / generate_questions / verify_profile），不写画像、用户编号或模型响应。20 秒是整次请求的总预算，TimeoutError 本身不能判断具体阶段；日志新增 stage 用于区分记忆读取、排队、生成与返回前复核。失败可重试，用户始终可以直接输入。前端切换模拟用户时立即隐藏旧结果、取消旧请求并丢弃迟到响应；不在 localStorage 持久化推荐。

## 验证与发布

后端覆盖身份与农场隔离、禁用记忆、无画像、删除/过期/版本变化、缓存有效期、刷新排除、模型格式与错误、未知能力/引用拒绝和 HTTP 鉴权；同时覆盖访谈式提问过滤、整批无效后重试、提示词更新失效缓存。前端覆盖动态渲染、换一批、身份切换竞态、失败重试，以及点击只填入、确认发送后将原问题交给 Agent。

无需数据库迁移，需发布 Agent 与管理端。推荐会调用已配置模型并产生用量；测试中的画像与样例为构造数据，不代表线上用户。当前不提供点击反馈训练或原始历史重排，兴趣更新依赖现有记忆流程。


## 推荐卡片展示

卡片采用双列横向布局，问题正文为主，来源使用兴趣/探索图标轻提示；移除逐卡重复的底部来源文案。问题最多展示两行，按钮可访问名称、悬停提示和点击填入均保留完整原文。换一批使用轻量按钮，等待时以同尺寸六卡骨架避免内容区收缩；错误和空结果仍提供清楚的下一步。

聊天区宽度不超过 620px 时切换单列，避免会话侧栏挤压正文。沿用亮暗主题令牌，支持键盘焦点与系统减少动态效果设置。点击和 Enter 激活只填入并聚焦输入框，不自动发起对话。视觉验证使用构造问题，覆盖亮色、暗色、窄屏和骨架状态。
