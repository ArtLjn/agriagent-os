# 会话归档与草稿箱

## 用户行为

Playground 会话列表提供“归档到草稿箱”，生成中的会话暂不可归档。本地消息未持久化时也不显示可用归档操作。“会话 / 草稿箱”切换分别加载对应列表，两类列表均支持分页。归档当前会话后开启空白会话，草稿箱历史只读；恢复后可回到会话列表继续聊天。

草稿箱提供恢复和删除。删除先确认，失败保留会话并允许重试；成功后无法恢复。删除仅作用于这段会话的可用性，不删除已经保存的个性化记忆，确认框明确说明这一点。切换用户会销毁旧目录和确认框，迟到请求不能更新新身份的数据。

## 模块边界

- `agent/platforms/persistence/mongo/conversation_catalog.py` 由 conversations API 与 chat API 调用，负责目录聚合、归档状态变更和访问校验；连接仍由 chat_store 提供。原有列表函数移入该模块并保留原入口重导出，避免向接近 1000 行的消息存储文件继续添加生命周期逻辑。
- `ConversationSidebar.tsx` 由 Playground 页面调用，负责列表分页、分类、操作确认及请求竞态；父页面继续管理聊天流和当前会话。提取已有侧栏 JSX，避免在大型页面中混入新的目录状态机。
- 推荐改动在原有生成服务与提示词中完成，不新增模型客户端或记忆存储。

## 数据模型与接口

使用现有 conversationStates，沿用 `(userId, farmId, conversationId)` 唯一索引，按需初始化目录字段：`archived`、`archivedAt`、`lifecycle=deleted`、`deletedAt`。缺少这些字段的历史会话默认未归档，无需回填。归档操作不改动 conversationRevision、summary 或 pendingAction，不取消已开始的业务执行。

删除是不可恢复的逻辑删除，聊天正文、历史摘要和审计记录继续按现有存储策略保留，本功能不提供物理擦除。写入删除标记后，目录聚合、会话详情、消息、Turn 列表与详情、新聊天入口均拒绝访问；并发迟到结果不会使已删除会话重新出现在列表。删除和恢复竞争时，原子条件更新禁止覆盖删除标记。旧客户端已开始的执行仍按原执行生命周期结束。

- GET `/api/v2/conversations?archived=false|true`：过滤在分页限制之前执行；聚合关联状态时同时匹配当前用户和农场，避免相同会话编号串租户。错误返回 503，不把存储错误显示为草稿箱为空。
- PATCH `/api/v2/conversations/{id}`，body `{ "archived": true|false }`：严格布尔值，禁止额外字段，要求 conversation:write。
- DELETE `/api/v2/conversations/{id}`：仅允许删除已归档会话；重复删除幂等，其他租户或不存在的会话均为 404。
- `/chat`：归档会话返回 conversation_archived（409），已删除会话返回 conversation_not_found（404）。
