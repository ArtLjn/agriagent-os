# 自动学习与记忆归并

用户正常聊天即可积累稳定偏好，不必说“记住”，不必逐条审核。后台抽取有效观察后直接生效：喜欢西瓜、后来补充喜欢草莓会归并到水果偏好；明确说不再喜欢西瓜时更新冲突部分，保留草莓偏好。用户在记忆管理页查看分类、来源和证据数，随时编辑或删除。

参考本地 `ocean/mnemo-mcp` 的 auto_observe、分类去重和 Dream 语义合并，复用当前 Mongo 存储与 Worker。没有引入另一套记忆服务，没有新增主系统提示词，抽取与归并只在后台局部模型调用中运行。没有实现全库定时 Dream 或使用次数驱动的正确性反馈。

## 数据与协议

- Settings 的 auto_learn_enabled 默认 true。旧文档未显式选择时采用新默认，明确关闭保留；load 仅做兼容投影，下一次正常 CAS 写入才持久化。
- Memory 新增 category：profile（个人背景）、preference（兴趣偏好）、work（工作习惯）、response（交流方式）、general（其他）。旧记录缺省 general，原 kind/scope 字段不变。
- 用户消息与 `memoryLearningV2={status:pending,farm_uid,observed_at}` 在同一文档原子写入。后台先幂等创建 `agentMemoryLearningTasksV2` 任务再确认事件；中途崩溃可重放。事件字段与任务集合同时版本化，避免旧消费者抢任务后绕过原子事实校验。临时会话不写事件，部署前没有新版事件的历史消息不会被扫描重学。
- 学习任务保存服务端接受时间 observed_at、代次、租约和实际 applied_count/reason/memory_ids。done 不等于写入：无稳定事实或控制状态变化可为零写入，最终失败有 error_code。任务结束后清掉原文。
- 主题卡片内 `atoms` 保存独立事实：slot（对象、属性及条件，不含正负值）、text、source_type、source_message_ids、evidence_turns/count、revision、valid_from、last_observed_at、updated_at。最多 30 条，展示 text 由服务端连接事实生成，保持原有卡片 ID 和管理 API。
- 纠正只替换目标 slot，并重置该值的证据；其他事实的正文、来源、证据和时序保持不变。同一轮显式工具与后台均观察到事实时只计一次，显式保存可提升来源。证据次数不是模型准确率。
- `GET /api/v2/me/memories` 新增 category 筛选。`POST` 的 category 可选，缺省 general。Web 展示分类并支持筛选；移动端延用同一接口和编辑删除入口。
- 无 SQL 变更，也不需要强制 Mongo 迁移。发布 Agent 和管理端；移动端说明随客户端发布更新。旧 candidate 不因部署直接变为有效记忆。

## 正确性边界

观察来自持久化的普通用户消息，不依赖助手是否成功。敏感、临时、引用和不确定内容跳过。先独立抽取，再选择当前用户/农场可见的最多 30 条记忆对齐，同 key、词汇相关度、分类依次优先。超出窗口仍可能重复，尚无全库离线压缩。个人兴趣使用 user 范围；有农场限定的习惯使用 user_farm。个人新观察可纠正当前可见的旧农场范围同一事实，沿用旧范围，不跨农场改写。

new 新主题、reinforce 同义事实、merge 同主题不同对象、contradict 同一事实的新取值。模型只选择主题 ID 和目标 slot，禁止重写整段 merged_text。证据必须是用户原文的连续子串，任一伪造证据或同批同 slot 冲突导致整批重试，不能静默丢掉部分事实再报成功。

抽取后、归并前增加独立完整性校验：必须覆盖全部稳定事实、每条只含一个可独立纠正的对象属性、无新增推测，并在每条正文保留项目或场景限定。空抽取也核对遗漏；任一项不通过，整批进入既有有限重试，禁止错误原子覆盖旧值。每轮后台学习增加一次短模型调用，仍受原有租约和超时约束。

旧卡片只在涉及更新时拆成原子事实，逐字证据与独立等价性校验均通过后，随本次 CAS 一起提交；迁移不增加证据。无法无损拆分时保留旧内容，有限重试后报错。手工设置始终优先；自动纠正手工事实必须晚于其更新时间，普通补充不能改写原有事实。

归并期间数据变化触发版本冲突，重新读取和抽取后重试；提交前再次校验租约及用户控制代次。每个事实分别校验观察时间，旧任务不能回滚新偏好，也不会因同主题另一事实更新而丢掉无关补充。删除/清空增加控制代次，清除正文、atoms、来源、证据和归并说明，索引沿用版本回查与异步删除；用户原始聊天记录遵守既有会话保留策略。记忆不授予业务写权限。

召回先做相关性过滤，再排序取最多 5 条；语义命中、文字相关或交流方式记忆才进入非空查询的上下文。中文使用重叠双字，避免“吃葡萄”切词后漏掉葡萄。无 RAG 时仍能文字召回，但同义改写召回能力受限。

## 显式工具与验证

`manage_personal_memory` 的 list 为 read，其余动作是写入尝试；是否成功落库独立记录 persisted，不将失败写入当作完成证据。显式请求支持承接近期用户内容，当前确认与事实来源分别核对，无需完整复述。该核对是服务端执行校验，不是每条自学习记忆的用户审核。

记忆投影携带真实 memory_id 和 revision。update/forget 的目标由服务端按当前身份读取；普通“我不喜欢葡萄了”交后台学习，无需明确长期授权。明确请求立即保存时，工具经授权与内容核验后也调用同一原子抽取、对齐和 CAS 提交流程；局部否定不能据此删除整条复合偏好。提交前核对审查时的目标版本。

普通观察误走工具返回 memory_observation_only，明确 persisted=false、retryable=false。纯偏好当轮正常收尾，让 Worker 按用户设置学习；混合任务继续业务调用，但不再次调用记忆写工具。不可重试错误立即收尾；编号/版本/证据等可修复错误最多允许一次修复，避免消耗全部步数后才触发死循环保护。固定的非持久化答复复用已确认的观察结论，不再反复审查。

授权审查先按本轮用户原文判断意图，不能从模型生成的 update 动作或旧 evidence 推导显式授权；普通偏好纠正的 requests_persistence/authorized 均为 false，preference_statement 为 true。

新增 `facts.py` 是纯数据领域边界，调用方为学习提交、召回和存储遗忘；隔离原子事实时序与来源规则，避免现有学习模块同时混入数据变换和模型/队列 I/O。其余逻辑继续复用原模块，没有新服务。

`test_memory_unified.py` 覆盖独立事实、事件恢复、乱序、删除和共享提交边界。工具授权测试隔离学习模型，不能代替服务验收。`AGENT_MEMORY_E2E=1` 开启 `test_memory_e2e.py`：真正 HTTP/SSE、模型、Mongo、Redis、Worker、重启和新会话；随机专属库/前缀退出时精确清理。空 MCP 协议服务隔离农场业务权限，RAG 在该测试中关闭，因此不声称覆盖真实农场业务或线上向量检索。

`GET /api/v2/health` 的 runtime 返回 started_at 和 memory_build。指纹在启动时固定，修改磁盘不会让旧进程假装已更新；发布后必须重启并核对指纹。
