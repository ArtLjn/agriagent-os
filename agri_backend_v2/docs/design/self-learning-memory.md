# 自动学习与记忆归并

用户正常聊天即可积累稳定偏好，不必说“记住”，不必逐条审核。后台抽取有效观察后直接生效：喜欢西瓜、后来补充喜欢草莓会归并到水果偏好；明确说不再喜欢西瓜时更新冲突部分，保留草莓偏好。用户在记忆管理页查看分类、来源和证据数，随时编辑或删除。

参考本地 `ocean/mnemo-mcp` 的 auto_observe、分类去重和 Dream 语义合并，复用当前 Mongo 存储与 Worker。没有引入另一套记忆服务；抽取与归并在后台局部模型调用中运行，回答阶段另有有界的记忆阅读与使用契约。没有实现全库定时 Dream 或使用次数驱动的正确性反馈。

## 数据与协议

- Settings 的 auto_learn_enabled 默认 true。旧文档未显式选择时采用新默认，明确关闭保留；load 仅做兼容投影，下一次正常 CAS 写入才持久化。
- Memory 新增 category：profile（个人背景）、preference（兴趣偏好）、work（工作习惯）、response（交流方式）、general（其他）。旧记录缺省 general，原 kind/scope 字段不变。
- 用户消息与 `memoryLearningV3={status:pending,farm_uid,observed_at}` 在同一文档原子写入。后台先幂等创建 `agentMemoryLearningTasksV3` 任务再确认事件；中途崩溃可重放。事件字段与任务集合同时版本化，避免旧消费者抢任务后绕过原子事实校验。临时会话不写事件，部署前没有新版事件的历史消息不会被扫描重学。
- 学习任务保存服务端接受时间 observed_at、代次、租约和实际 applied_count/reason/memory_ids。done 不等于写入：无稳定事实或控制状态变化可为零写入，最终失败有 error_code。任务结束后清掉原文。
- 主题卡片内 `atoms` 保存独立事实：slot（对象、属性及条件，不含正负值）、text、source_type、source_message_ids、evidence_turns/count、revision、valid_from、last_observed_at、updated_at。最多 30 条，展示 text 由服务端连接事实生成，保持原有卡片 ID 和管理 API。
- 纠正只替换目标 slot，并重置该值的证据；其他事实的正文、来源、证据和时序保持不变。同一轮显式工具与后台均观察到事实时只计一次，显式保存可提升来源。证据次数不是模型准确率。
- `GET /api/v2/me/memories` 新增 category 筛选。`POST` 的 category 可选，缺省 general。Web 展示分类并支持筛选；移动端延用同一接口和编辑删除入口。
- 无 SQL 变更，也不需要强制 Mongo 迁移。发布 Agent 和管理端；移动端说明随客户端发布更新。旧 candidate 不因部署直接变为有效记忆。

## 正确性边界

观察来自持久化的普通用户消息，不依赖助手是否成功。敏感、临时、引用和不确定内容跳过。先独立抽取，先按当前用户/农场的 slot、主题、稀有词索引及可选语义索引召回有界候选，再选择最多 30 条、12KB 证据对齐，精确 slot 优先于主题和词相关度。多个候选分别分配归并窗口，避免旧事实被其他主题挤出；未配置语义检索时，同义改写仍可能重复，尚无全库离线压缩。个人兴趣使用 user 范围；有农场限定的习惯使用 user_farm。个人新观察可纠正当前可见的旧农场范围同一事实，沿用旧范围，不跨农场改写。

new 新主题、reinforce 同义事实、merge 同主题不同对象、contradict 同一事实的新取值。模型只选择主题 ID 和目标 slot，禁止重写整段 merged_text。证据必须是用户原文的连续子串，伪造证据导致整批重试；同批同 slot 矛盾保留为 conflicted，不能静默代选或丢弃事实。

抽取后、归并前增加独立完整性校验：必须覆盖全部稳定事实、每条只含一个可独立纠正的对象属性、无新增推测，并在每条正文保留项目或场景限定。空抽取也核对遗漏；任一项不通过，整批进入既有有限重试，禁止错误原子覆盖旧值。每轮后台学习增加一次短模型调用，仍受原有租约和超时约束。

旧卡片只在涉及更新时拆成原子事实，逐字证据与独立等价性校验均通过后，随本次 CAS 一起提交；迁移不增加证据。无法无损拆分时保留旧内容，有限重试后报错。手工设置始终优先；自动纠正手工事实必须晚于其更新时间，普通补充不能改写原有事实。

归并期间数据变化触发版本冲突，重新读取和抽取后重试；提交前再次校验租约及用户控制代次。每个事实分别校验观察时间，旧任务不能回滚新偏好，也不会因同主题另一事实更新而丢掉无关补充。删除/清空增加控制代次，清除正文、atoms、来源、证据和归并说明，索引沿用版本回查与异步删除；用户原始聊天记录遵守既有会话保留策略。记忆不授予业务写权限。

旧兼容投影 `context_text` 按相关性排序取最多 5 张卡；正式 Runtime 改用下述任务阅读与依据注入，不能把命中卡片数当成回答利用效果。中文使用重叠双字，避免“吃葡萄”切词后漏掉葡萄。无 RAG 时仍能文字召回，但同义改写召回能力受限。

## 显式工具与验证

`manage_personal_memory` 的 list 为 read，其余动作是写入尝试；是否成功落库独立记录 persisted，不将失败写入当作完成证据。显式请求支持承接近期用户内容，当前确认与事实来源分别核对，无需完整复述。该核对是服务端执行校验，不是每条自学习记忆的用户审核。

记忆投影携带真实 memory_id 和 revision。update/forget 的目标由服务端按当前身份读取；普通“我不喜欢葡萄了”交后台学习，无需明确长期授权。明确请求立即保存时，工具经授权与内容核验后也调用同一原子抽取、对齐和 CAS 提交流程；局部否定不能据此删除整条复合偏好。提交前核对审查时的目标版本。

普通观察误走工具返回 memory_observation_only，明确 persisted=false、retryable=false。纯偏好当轮正常收尾，让 Worker 按用户设置学习；混合任务继续业务调用，但不再次调用记忆写工具。不可重试错误立即收尾；编号/版本/证据等可修复错误最多允许一次修复，避免消耗全部步数后才触发死循环保护。固定的非持久化答复复用已确认的观察结论，不再反复审查。

授权审查先按本轮用户原文判断意图，不能从模型生成的 update 动作或旧 evidence 推导显式授权；普通偏好纠正的 requests_persistence/authorized 均为 false，preference_statement 为 true。

新增 `facts.py` 是纯数据领域边界，调用方为学习提交、召回和存储遗忘；隔离原子事实时序与来源规则，避免现有学习模块同时混入数据变换和模型/队列 I/O。其余逻辑继续复用原模块，没有新服务。

`test_memory_unified.py` 覆盖独立事实、事件恢复、乱序、删除和共享提交边界。工具授权测试隔离学习模型，不能代替服务验收。`AGENT_MEMORY_E2E=1` 开启 `test_memory_e2e.py`：真正 HTTP/SSE、模型、Mongo、Redis、Worker、重启和新会话；随机专属库/前缀退出时精确清理。空 MCP 协议服务隔离农场业务权限，RAG 在该测试中关闭，因此不声称覆盖真实农场业务或线上向量检索。

`GET /api/v2/health` 的 runtime 返回 started_at 和 memory_build。指纹在启动时固定，修改磁盘不会让旧进程假装已更新；发布后必须重启并核对指纹。

## 规模、冲突与最终上下文预算（2026-10-24 追加）

超过 200 张卡片时，下次写入迁移到 `agentMemoryRecordsV3` 独立正文集合。用户根文档只保留设置、控制代次、版本和 `memory_id → 不可变正文ID` 清单。先写正文，再以用户版本 CAS 发布清单；单节点 Mongo 无需事务。读取先按索引取有界候选，再投影这些 ID 的当前引用核对发布状态，不下载全库正文或整个清单。更新只写改变的正文，旧正文提交后删除，异常遗留由有宽限期的回收器检查清单与发布版本后清理。最多 10000 张有效卡片，清单 BSON 另设 12MiB 上限；不是无限容量，用户级 CAS 下并发修改仍可能有限重试。管理 API 使用数据库分页，过期筛选和总数同一口径。

原子事实新增 `conditions`、`temporal_scope`、`time_evidence`、`state`。当前与历史分别保存，历史必须有原文时间依据；模型遗漏时间字段不能通过独立复核。明确纠正保留最多 5 个历史版本；同轮无顺序的互相矛盾保留最多 3 个备选，标记 conflicted，在用户澄清前不作为已知现状。重复次数不决定真伪，不同项目条件不互相覆盖。条件归并明确输出 `conditions_equivalent`：语义相同的“喝拿铁”和“喝拿铁时”复用旧条件，真正不同的场景仍分别保存；不能用字符串不等代替场景差异。旧值仅在明确历史查询时投影；删除清除当前、历史、备选及证据全部正文。本实现保留自然语言时间证据，没有实现完整的自然语言日期区间解析。

模型请求在消息、工具 schema、工具参数和返回结果全部组装后再计量。兼容网关没有统一 tokenizer，因此用 UTF-8 字节上界加协议余量，Trace 明示 `utf8_upper_bound`，不是精确计费。记忆投影独立受 3000 字符与 3000 保守 token 双预算约束；最终请求还预留回复和安全余量。超限优先移除可重检索背景，再把过大工具返回替换成完整、带缺失说明的状态 JSON，保留工具调用配对。必需系统契约或当前用户输入仍超限则返回 `context_budget_exceeded`，不调用 Provider；后台抽取与复核证据超限直接拒绝，不截半段证据。

Qwen3.6 Flash 使用 64000 的保守工作预算；厂商窗口可更大，但不会把全库塞进提示。网关额度可通过 `CONTEXT__MODEL_CONTEXT_TOKENS` 覆盖。摘要保留目标、约束、已确认结果和未完成事项；摘要不具有长期记忆授权或事实权威。

Runtime 写入 `final_llm_context` 节点，记录发送前的最终预算和消息。大于 Trace 体积上限时，仍保留数值预算与结构化消息预览，并标记 `__trace_truncated`，避免整份 JSON 截断后观测面板显示为空。预览不是完整原始请求，也不改变实际发送内容。“根据已保存的记忆”属于读取引用，写入护栏不能误报成本轮保存声明；同一句后面真的声称创建业务记录时，仍执行原写入核验。

新增模块边界：`context/budget.py` 由 Runtime 和 LLM Client 共用最终请求校验；`memory/inference.py` 从接近文件预算的学习模块中分离模型抽取、复核和归并；`mongo/memory_records.py` 封装独立正文、索引、清单发布和回收。没有新服务或第三方依赖。

发布必须同时升级 Agent 入口与 Worker，事件、任务集合和 outbox 索引均使用 V3。旧队列在停旧消费者前排空或显式处理，不自动重学历史消息。内嵌格式延迟迁移，但已转 V3 的账号不能直接降级到只读内嵌旧版本；回滚需先停写并按发布清单重建兼容数据，超过单文档容量时不能直接重建。真实账号的规模验收会触发此存储升级。

复现：普通回归运行记忆、上下文、Runtime 测试；`AGENT_MEMORY_STRESS=1 pytest tests/test_memory_scale.py` 在随机独立 Mongo 库验证 1000/10000 卡片、12 并发读取、CAS、删除、未发布版本与回收。`AGENT_MEMORY_E2E=1 pytest tests/test_memory_e2e.py` 使用实际模型和 HTTP/SSE/Redis/Worker，并核对重启、跨会话、历史隔离与删除。默认跳过外部集成，不用 mock 结果冒充真实服务通过。

## 面向回答的记忆阅读与注入（2026-10-24 追加）

### 方法依据与适用边界

- [LongMemEval §5.5](https://arxiv.org/html/2410.10813v2#S5.SS5) 在正确证据已全部给出的实验中，将读取与最终回答分开，比较直接阅读、先抽取关键依据和结构化呈现。它支持单独评估“记忆用得对不对”，不能只用检索命中率验收。本文采用受控事实引用实现这一思路，不宣称复现论文分数，也不保存模型隐式推理。
- [Lost in the Middle](https://arxiv.org/abs/2307.03172) 的实验提示长上下文中的位置会影响证据使用。这里把任务依据移到当前问题之前，并在每步更新时保持单份；这只是工程选择，当前 Qwen 模型的收益需实测。
- [Anthropic 上下文工程](https://www.anthropic.com/research/effective-context-engineering-for-ai-agents) 建议选择少量高价值内容、分清指令和数据，并结合预先加载和按需检索。这里最多补查一次，不构建无界自主搜索循环。

这些来源没有给出对所有模型都最优的记忆注入方式。小规模对照同时保留旧注入的答案，判断是否确有改善；当前模型、3000 条生活语料与真实业务工具仍需单独验收。

### 运行链路

1. `long_term` 取得当前账号、农场、有效期和发布版本约束下的有界候选。`personalization.context_candidates` 按完整主题卡片分配原子事实预算，最多 60 条、12KB；同卡的正面偏好和排除条件一起进入阅读，超预算整卡跳过，不能只装正面事实后误称没有排除项。超大卡片会降低本次覆盖率，不能把未入选解释为账号没有记忆，也不全量注入账号的 3000 条记忆。
2. `inference.read_context` 根据当前问题与最多最近两条对话整理依据，只输出候选索引、用途、适用性和推荐方面。没有自由生成的事实正文；服务端回填原文和条件。回答、推荐、避开、表达、澄清分别组织，冲突事实由服务端强制标为待澄清。推荐同一方面只保留一条；直接事实问答仍可对比同一属性的不同条件。
3. 依据不足时允许最多两个短查询、一次补查、第二次阅读；禁止第三轮扩展。补查使用均分词项候选预算的覆盖模式，避免低频噪声把“在家”等场景词完全挤掉；原有普通检索保持稀有词策略。候选融合后重新执行 60 条/12KB 限制。语义阅读总时限由 `MEMORY_CONTEXT_COMPILE_TIMEOUT` 控制，默认 12 秒；存储每次边界仍受 `MEMORY_CONTEXT_TIMEOUT` 默认 1.5 秒限制。阅读超时/无效输出仅保留表达设置和 `unavailable` 状态，不伪装成空记忆库。
4. 发布前精确重读所选记录和控制版本。并发删除、关闭读取、跨农场、过期均不能由缓存恢复。一个 Turn 内以账号/农场/问题/版本复用阅读结果，每步仍校验权威数据；压缩历史也复用同轮缓存，下一轮重新整理。
5. `answer_context` 渲染完整事实而不截断句子，优先保留避开事项与冲突，整块最多 3000 字符与 3000 保守 token。只保留可用于后续精确删除或纠正的 memory_id，slot 和更新时间留在 trace，减少无用元数据。它是 `user` 层数据，不能升级权限。静态系统契约要求实际用适用偏好选择建议，并自然说明联系；不能仅复述清单后给通用答案。
6. `builder` 与 Runtime 将依据放在当前问题之前。业务工具仍按原协议可用；生活问题不得仅因农事身份去查工单，混合请求仍需查询真实业务事实。

收尾审查如果判断需要补执行长期保存，会只用用户原文与授权对话独立复核意图，不把助手草稿“已更新”当成用户授权。普通偏好没有写入回执时不能虚称“记住了”；继续由后台学习处理，混合业务结果仍按原写入核验流程返回。

记忆工具 list 按 query 检索主题，省略时使用本轮问题，最多返回 8 条候选；移除误导模型反复翻页的 has_more，不再每次把同一批 60 条全库记录塞入上下文。

记忆工具漏填 evidence 时，服务端可使用长度允许的完整本轮用户原文；不截断、不替换模型伪造的引用，仍核验本轮意图、目标记录归属、删除范围和内容依据。这只修复参数遗漏，不放宽写入授权。读取未命中时只描述本次缺少相关依据，不能推断整个账号只有表达设置。注入数据分别给出完整库未加载、本次事实数量和存储清单最近发布时的有效记忆计数；未知计数保持 null，不伪装成零。

`answer_memory_context` 记录候选数、选中数、实际注入数、来源、补查词、缓存命中与耗时。`final_llm_context.memory_context_included` 在最终请求预算裁剪后记录是否真的发送记忆块；即使 Trace 只保存预览也保留这个标志。前者表示渲染成功，后者才表示进入了本次模型请求，两者不能混为一谈。没有自动宣称回答已利用成功：利用效果需要检查最终回答。

本次复用 `inference` 的模型边界、`personalization` 的纯投影、`long_term` 的存储编排和既有上下文组装，不新增生产模块、服务、数据库或依赖。新增 `tests/test_memory_context_use.py` 独立覆盖读取、注入及实际回答，避免与学习写入测试混为同一个指标。

### 回归方式

- 普通回归覆盖索引引用校验、删除竞态、关闭读取、临时模式、账号/农场/问题隔离、无版本变化的过期、编译超时、单轮补查、冲突、去重、完整事实预算和注入位置。
- `AGENT_MEMORY_READING_LIVE=1 pytest tests/test_memory_context_use.py` 使用真实模型，输入相同的正确候选，对比旧原始注入与新的任务依据；覆盖居家推荐、事实回忆、当前请求覆盖和农场限定。报告保存在 pytest 临时目录的 `reading-comparison.json`。这是小样本回归，不能代替广泛的质量评测。
- `AGENT_MEMORY_STRESS=1 pytest tests/test_memory_scale.py` 增加 3000 条自然生活语料、12 并发缓存发布。此项模型为替身，只测存储、预算和缓存，不冒充语义质量或完整模型延迟。
- `AGENT_MEMORY_E2E=1 pytest tests/test_memory_e2e.py` 继续覆盖实际 HTTP/SSE、自动学习、纠正、重启、跨会话召回和删除。

## 主动召回与低延迟改造（2026-10-24）

本节替代上一节默认依赖两轮阅读模型的在线路径；旧阅读器保留为 `read` 对照模式。默认 `retrieve` 在每轮回答前固定运行，不依赖用户说“记得”或模型选择记忆工具。提问原文与最近对话用于候选收集，设置常驻、事实按需召回；模拟生活记忆只用作质量与规模数据，不代表已验证的真实个人画像。

依据与取舍：
- [LongMemEval](https://arxiv.org/html/2410.10813v2#S5.SS5) 将检索与阅读能力分开评测，因此同时检查候选、最终请求和回答行为。
- [Letta 分层记忆](https://docs.letta.com/v1-sdk/memory/memory-blocks) 支持短小常驻信息与归档检索分层；本系统沿用独立 settings 与事实存储，无需新增第二套用户画像真相。
- [Azure 混合检索](https://learn.microsoft.com/en-us/azure/search/hybrid-search-overview) 使用关键词、向量与 RRF；本系统采用该方式并以多样性惩罚防止近似生活记忆占满上下文。此处是可解释的排序，并未声称部署了神经重排器。
- [Anthropic 上下文工程](https://www.anthropic.com/research/effective-context-engineering-for-ai-agents) 强调高信息密度与按需取用；本系统整卡预算、按需业务工具、默认移除额外阅读和步数预估模型调用。
- [Ollama Embeddings](https://docs.ollama.com/capabilities/embeddings) 要求索引和查询同模型；不同模型集合及清单隔离，可重建派生索引而不改原始记忆。

实现边界：`long_term` 是运行时固定入口；`personalization` 在现有模块内做融合、原文投影及预算；`memory_index` 只处理外部语义索引和清单，权限/状态最终由 Mongo 裁决。未新增生产模块或第二个事实源。异步学习继续只依据用户原文，不从回答推荐反向产生偏好。候选附条件/时效/来源，主模型根据本轮信息决定适用性，不因召回就断言事实。

验收清单：
- [x] 普通问题触发自动召回；快速路径不调用阅读器。
- [x] 超时仍可用词项依据，诊断区分未配置、超时与服务内部 BM25 降级。
- [x] 用户、农场、关闭、临时会话、删除和版本边界回归。
- [x] 整卡预算保存正负偏好；集合切换不误复用旧清单。
- [ ] 真实语义改写查询与真实回答质量验收。
- [ ] 3000/10000 规模与并发验证。
- [ ] Chrome 实际账号跨会话验证及临时数据清理。

生产放行前必须记录首字耗时、完整回答耗时、记忆耗时、实际语义降级率、预算、候选与注入依据；单条模型调用成功不能替代端到端或商用容量评估。
