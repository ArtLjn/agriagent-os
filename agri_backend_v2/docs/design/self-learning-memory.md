# 自动学习与记忆归并

用户正常聊天即可积累稳定偏好，不必说“记住”，不必逐条审核。后台抽取有效观察后直接生效：喜欢西瓜、后来补充喜欢草莓会归并到水果偏好；明确说不再喜欢西瓜时更新冲突部分，保留草莓偏好。用户在记忆管理页查看分类、来源和证据数，随时编辑或删除。

参考本地 `ocean/mnemo-mcp` 的 auto_observe、分类去重和 Dream 语义合并，复用当前 Mongo 存储与 Worker。没有引入另一套记忆服务，没有新增主系统提示词，抽取与归并只在后台局部模型调用中运行。没有实现全库定时 Dream 或使用次数驱动的正确性反馈。

## 数据与协议

- Settings 的 auto_learn_enabled 默认 true。旧文档未显式选择时采用新默认，明确关闭保留；load 仅做兼容投影，下一次正常 CAS 写入才持久化。
- Memory 新增 category：profile（个人背景）、preference（兴趣偏好）、work（工作习惯）、response（交流方式）、general（其他）。旧记录缺省 general，原 kind/scope 字段不变。
- 学习任务保存服务端接受时间 observed_at；自动记忆记录 last_observed_at。证据继续用 source_message_ids/evidence_turns，正文只保存当前合并结果，不另存敏感历史副本。
- `GET /api/v2/me/memories` 新增 category 筛选。`POST` 的 category 可选，缺省 general。Web 展示分类并支持筛选；移动端延用同一接口和编辑删除入口。
- 无 SQL 变更，也不需要强制 Mongo 迁移。发布 Agent 和管理端；移动端说明随客户端发布更新。旧 candidate 不因部署直接变为有效记忆。

## 正确性边界

观察只来自成功普通对话中的真实用户原文；敏感、临时、引用和不确定内容跳过。筛选后才与当前用户/农场可见记忆对齐，最多比较 30 条，同 key 和同分类优先。超过比较窗口的内容可能不能完全去重，尚无全库离线压缩。

new 新增、reinforce 加强同义记忆、merge 合并互补事实、contradict 更新明确纠正。多候选关联同一目标时必须给出一致的合并结果，协议错误有限重试；相同 key 但无语义关联不能直接覆盖。手工设置和手工编辑始终优先。

归并期间数据变化触发版本冲突，重新读取和抽取后重试；乱序旧任务不能回滚新偏好。同轮重试不重复计数。删除/清空增加控制代次并抹除正文，旧任务不能恢复。记忆不授予记账、工单等业务写权限。

## 显式工具与验证

`manage_personal_memory` 的 list 为 read，其余动作是写入尝试；是否成功落库独立记录 persisted，不将失败写入当作完成证据。显式请求支持承接近期用户内容，当前确认与事实来源分别核对，无需完整复述。该核对是服务端执行校验，不是每条自学习记忆的用户审核。

新增 `test_memory_learning.py` 覆盖后台观察、合并、分类和并发；`test_memory_authorization.py` 覆盖显式工具跨轮授权。原生命周期测试已接近 1000 行，按这两个独立边界新增测试文件，生产逻辑仍在现有模块。真实模型回放只写测试内存替身，不写生产用户数据。
