## Context

完整交付 Web、移动端、Agent 长期偏好能力，保留现有工作区 UI 改动。实现详情和部署参数以 `agri_backend_v2/docs/spec/2026-10-20-agent-personalization-long-term-memory-plan.md` 的实施结果章节为准。

## Goals / Non-Goals

实现设置、明确记忆、自动学习、临时模式和语义召回。生产发布及真实部署环境验收单独进行；不迁移实时业务事实、不修改业务权限、不写公共知识集合。

## Decisions

- 复用 Mongo 连接，配置和有限记忆使用单文档 CAS；删除、控制代次与索引待处理标记原子保存。不依赖多文档事务。
- Mongo 是主数据，QuillRAG 是可重建派生索引；独立集合、身份过滤、版本回查、异步删除。
- 对话工具由 Runtime 注入可信身份，写入证据只取当前或近期用户原文，本轮必须有明确操作意图。临时会话不开放记忆工具。
- 学习和索引各有独立后台循环。学习任务通过租约恢复、有限重试、独立证据和代次阻挡控制。设置明确值优先于推断。
- 用户消息与待投递学习事件同文档原子写入，后台幂等投递，不依赖主对话成败。部署前无事件的消息不自动重学。
- 主题卡片内保存独立 atoms，旧记录按需拆分并核验等价；模型对齐主题及 slot，服务端逐事实更新。显式保存与后台共用提交，局部纠正不连带改写其他事实。
- 来源和时间按事实保留；新值重置证据，同轮多路径只计一次。遗忘清除正文、atoms、证据与归并说明，保留防重放屏障。
- 两端复用相同配置 API，无本地有效配置副本；失败显示错误并保留编辑。

## Risks / Trade-offs

单用户有效记录上限 200，每主题最多 30 条事实，删除屏障持续保留。稳定非敏感观察默认直接生效，用户可关闭及删除；旧候选不因部署直接转正。模型抽取和归并仍可能出错，结构与原文证据校验不能证明语义百分之百正确；比较窗口最多 30 条，暂未实现全库离线整理。敏感拦截为确定性规则加模型约束，不保证识别任意敏感内容。Mongo/RAG 故障时对话降级；消息投递故障保留待投递事件重试，任务领取后有限重试并抹除原文。隔离集成测试不代表生产已部署，真实线上 RAG 另行验收。
