## ADDED Requirements

### Requirement: 配置持久化与并发

系统 SHALL 按可信用户身份读取和原子更新个性化配置，拒绝过期版本和未定义字段。

#### Scenario: 并发更新
- **WHEN** 两次请求提交同一预期版本
- **THEN** 只有一个更新成功，另一个返回版本冲突

### Requirement: 明确记忆范围与删除

系统 SHALL 只展示当前用户的全局及当前农场记忆，删除和清空影响后续读取，清空覆盖本人全部农场的个人记忆。

#### Scenario: 切换农场
- **WHEN** 用户切换农场
- **THEN** 不返回原农场限定的记忆

#### Scenario: 删除后旧索引仍存在
- **WHEN** 检索返回已删除或旧版本记录
- **THEN** Mongo 权威版本回查拒绝该记录进入个性化投影

### Requirement: 真实响应与上下文

系统 SHALL 将有效设置注入后续对话，存储故障不得伪装成功，设置和记忆保持用户级权限。

#### Scenario: 接口故障
- **WHEN** 真实后端返回异常
- **THEN** 客户端显示错误并保留编辑，不改用演示数据报告保存成功

### Requirement: 对话明确记忆工具

系统 SHALL 通过受控工具实现明确记忆操作，事实证据引用当前或近期用户原文，本轮操作意图须明确，身份与版本由服务端提供。

#### Scenario: 临时要求
- **WHEN** 用户仅要求本次详细回答
- **THEN** 没有长期修改意图的工具调用被拒绝，不改变长期设置

### Requirement: 临时对话

系统 SHALL 为临时对话隔离会话空间，不读取个性化、不开放长期记忆工具、不生成学习任务。

#### Scenario: 恢复临时会话
- **WHEN** 客户端传入已有 temporary 前缀的会话 ID
- **THEN** 服务端保持临时模式，即使客户端遗漏布尔开关

### Requirement: 受控自动学习

系统 SHALL 默认开启自动学习并保留用户显式关闭选择，只从带学习事件的新普通用户消息提取稳定、非敏感的个人事实，自动生效且无需逐条确认。明确设置优先，不把农场业务数据学习为个人偏好。

#### Scenario: 主对话失败或进程重启
- **WHEN** 用户消息已持久化，但助手失败或学习事件尚未投递时进程退出
- **THEN** 后台恢复幂等投递并处理，不重复累计同一轮证据

#### Scenario: 纠正复合偏好的一项
- **WHEN** 旧记忆包含多种水果，用户说不喜欢葡萄了
- **THEN** 按原子事实只更新葡萄，重置该值证据，保留其他水果及其来源和时序；普通纠正不因缺少显式长期授权而使主对话失败

#### Scenario: 显式保存与自动观察同时发生
- **WHEN** 同一轮明确保存请求同时被后台观察
- **THEN** 两条路径共用归并提交，不生成重复事实或重复证据，显式来源可被保留

#### Scenario: 删除原子记忆
- **WHEN** 用户删除或清空记忆
- **THEN** 清除正文、原子事实、来源证据和归并说明，并阻止旧任务或旧索引恢复它

#### Scenario: 开关或清空阻挡旧任务
- **WHEN** 用户关闭学习、关闭后重开或清空记忆
- **THEN** 控制变化前的请求和待处理任务不得重新写入旧记忆

### Requirement: 可恢复语义索引

系统 SHALL 使用独立 QuillRAG 集合，按可信身份过滤，采用不可变版本 ID、持久待处理标记与索引清单恢复同步。

#### Scenario: RAG 不可用
- **WHEN** 语义检索失败或超时
- **THEN** 使用结构化记忆和核心配置继续回答，不阻塞主业务流程

### Requirement: 双端配置

Web 和 Flutter SHALL 使用同一 Agent 配置与记忆接口，并使加载提示和执行过程偏好影响各自的对话界面。

#### Scenario: 移动端确认候选
- **WHEN** 用户确认候选记忆
- **THEN** 携带记录版本写入服务端，成功后刷新；失败保留原状态并提示
