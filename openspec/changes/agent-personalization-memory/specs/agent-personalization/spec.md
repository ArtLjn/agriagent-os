## ADDED Requirements

### Requirement: 配置持久化与并发

系统 SHALL 按可信用户身份读取和原子更新个性化配置，拒绝过期版本和未定义字段。

#### Scenario: 并发更新
- **WHEN** 两次请求提交同一预期版本
- **THEN** 只有一个更新成功，另一个返回版本冲突

### Requirement: 明确记忆范围与删除

系统 SHALL 只展示当前用户的全局及当前农场记忆，删除和清空影响后续读取，清空覆盖本人全部农场的个人记忆。

#### Scenario: 切换农场
- **WHEN** 用户切换农场
- **THEN** 不返回原农场限定的记忆

#### Scenario: 删除后旧索引仍存在
- **WHEN** 检索返回已删除或旧版本记录
- **THEN** Mongo 权威版本回查拒绝该记录进入个性化投影

### Requirement: 真实响应与上下文

系统 SHALL 将有效设置注入后续对话，存储故障不得伪装成功，设置和记忆保持用户级权限。

#### Scenario: 接口故障
- **WHEN** 真实后端返回异常
- **THEN** 客户端显示错误并保留编辑，不改用演示数据报告保存成功

### Requirement: 对话明确记忆工具

系统 SHALL 通过受控工具实现明确记忆操作，写入必须引用本轮用户原文中的操作意图，身份与版本由服务端提供。

#### Scenario: 临时要求
- **WHEN** 用户仅要求本次详细回答
- **THEN** 没有长期修改意图的工具调用被拒绝，不改变长期设置

### Requirement: 临时对话

系统 SHALL 为临时对话隔离会话空间，不读取个性化、不开放长期记忆工具、不生成学习任务。

#### Scenario: 恢复临时会话
- **WHEN** 客户端传入已有 temporary 前缀的会话 ID
- **THEN** 服务端保持临时模式，即使客户端遗漏布尔开关

### Requirement: 受控自动学习

系统 SHALL 默认关闭自动学习，开启后只从新普通会话提取候选，以独立 Turn 和 Conversation 计数；明确设置优先，业务习惯需用户确认。

#### Scenario: 开关或清空阻挡旧任务
- **WHEN** 用户关闭学习、关闭后重开或清空记忆
- **THEN** 控制变化前的请求和待处理任务不得重新写入旧记忆

### Requirement: 可恢复语义索引

系统 SHALL 使用独立 QuillRAG 集合，按可信身份过滤，采用不可变版本 ID、持久待处理标记与索引清单恢复同步。

#### Scenario: RAG 不可用
- **WHEN** 语义检索失败或超时
- **THEN** 使用结构化记忆和核心配置继续回答，不阻塞主业务流程

### Requirement: 双端配置

Web 和 Flutter SHALL 使用同一 Agent 配置与记忆接口，并使加载提示和执行过程偏好影响各自的对话界面。

#### Scenario: 移动端确认候选
- **WHEN** 用户确认候选记忆
- **THEN** 携带记录版本写入服务端，成功后刷新；失败保留原状态并提示
