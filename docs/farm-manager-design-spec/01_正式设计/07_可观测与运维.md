# 07 — Trace 收集 JSON 设计

> 状态：草稿 | 维护：BlockShip | 关联：[01_Agent平台架构](./01_Agent平台架构.md)、[02_Skill引擎与契约](./02_Skill引擎与契约.md)、[06_数据飞轮与评测](./06_数据飞轮与评测.md)

## 1. 设计目标

Trace 的目标不是把日志搬进数据库，而是让一轮 Agent 请求可以被稳定回答：

- 这一轮经历了哪些节点？
- 每个节点看到了什么输入，产出了什么输出？
- Skill Router 为什么选择这些候选 Skill？
- 本轮是否调用了外部 RAG、embedding、LLM、工具？
- 慢在哪里，错在哪里，哪些证据缺失？
- 前端 TraceMonitor、调试脚本和数据飞轮能否读取同一份 JSON？

本文把 trace 收集设计收束为 JSON 契约。运行时仍使用当前 `TraceCollector.record()` 入口，节点级字段保持：

```json
{
  "request_id": "16249051",
  "session_id": "playground-1785203315960-jqvgbb",
  "farm_id": 2,
  "round_index": 1,
  "node_type": "skill_router",
  "node_name": "skill_router",
  "input_data": {},
  "output_data": {},
  "duration_ms": 22,
  "token_usage": null,
  "status": "success",
  "error_message": null
}
```

非目标：

- 不在默认 trace 中保存完整 prompt、完整历史消息、完整工具大结果。
- 不把 `app.log` 的人读日志当作机器可读事实源。
- 不在 Skill Router trace 中重复保存 `frames`、`evidence.frames`、`plan_draft.intent_frames` 三份同构数据。
- 不为了 debug 把敏感字段、密钥、完整鉴权头写入 trace。

## 2. 总体 Trace 节点概括

一轮用户请求由一个 request summary 和多条 node records 组成。

### 2.1 Request Summary

`traceRequests` 是一轮请求的摘要视图，用于 TraceMonitor 列表、根因卡片和告警入口。它可以由 `agent_turns`、`traceRecords`、`conversationMessages` 聚合得到，也可以在请求结束时异步写入。

```json
{
  "schema_version": 2,
  "request_id": "16249051",
  "session_id": "playground-1785203315960-jqvgbb",
  "turn_id": "118",
  "conversation_id": "conversation-118",
  "farm_id": 2,
  "environment": "dev",
  "entrypoint": "POST /agent/chat/stream",
  "status": "success",
  "status_reason": null,
  "started_at": "2026-07-28T09:xx:xx.xxx+08:00",
  "ended_at": "2026-07-28T09:xx:xx.xxx+08:00",
  "duration_ms": 19042,
  "node_count": 16,
  "round_count": 2,
  "summary": {
    "user_input_preview": "天气咋样",
    "reply_preview": "苏州市虎丘区未来三天天气预报：7月28日...",
    "selected_tools": ["weather"],
    "tool_calls": 1,
    "llm_calls": 2,
    "skill_calls": 1,
    "root_cause_hint": null
  },
  "metrics": {
    "agent_turn_latency_ms": 19042,
    "node_duration_sum_ms": 9056,
    "unattributed_duration_ms": 9986,
    "llm_duration_ms": 6422,
    "tool_duration_ms": 2425,
    "prompt_duration_ms": 9,
    "total_tokens": 3297
  },
  "evidence_status": {
    "mysql": {
      "status": "partial",
      "missing": ["trace_records", "conversation_messages"]
    },
    "mongo": {
      "status": "ok",
      "trace_nodes": 16,
      "messages": 2
    },
    "jsonl": {
      "status": "path_anchor_mismatch",
      "event_file": "data/agent-events/dt=2026-07-28/farm_id=2/session_id=playground-1785203315960-jqvgbb/events.jsonl"
    }
  },
  "root_error": null
}
```

字段说明：

| 字段 | 含义 |
| --- | --- |
| `schema_version` | trace JSON 契约版本；字段调整必须递增。 |
| `request_id` | HTTP 请求级 ID，是排查入口。短 ID 可以做前缀查询。 |
| `session_id` | 会话 ID，用于串联多轮消息。 |
| `turn_id` | 用户可见的一轮对话 ID；Mongo 中必须组合 `turn_id + session_id + farm_id` 查询。 |
| `round_count` | ReAct / 工具调用循环轮数。样本链路为 2 轮。 |
| `metrics.unattributed_duration_ms` | 请求总耗时减节点耗时之和，用于发现 SSE、持久化、网络等待或未埋点区域。 |
| `evidence_status` | 证据完整度。`mysql_partial` 不等于链路丢失，Mongo 可作为节点真相源。 |

### 2.2 Node Record

`traceRecords` 是节点级事实源。每个节点一条 JSON，不要求所有节点拥有同样的 `output_data`，但 envelope 必须一致。

```json
{
  "schema_version": 2,
  "record_id": "trace_record_id",
  "request_id": "16249051",
  "session_id": "playground-1785203315960-jqvgbb",
  "farm_id": 2,
  "round_index": 1,
  "node_type": "llm_call",
  "node_name": "Qwen/Qwen3-235B-A22B",
  "status": "success",
  "duration_ms": 1093,
  "input_data": {},
  "output_data": {},
  "token_usage": {
    "prompt_tokens": 1042,
    "completion_tokens": 232,
    "total_tokens": 1274,
    "usage_source": "provider"
  },
  "error_message": null,
  "start_time": "2026-07-28T09:xx:xx.xxx+08:00",
  "end_time": "2026-07-28T09:xx:xx.xxx+08:00",
  "created_at": "2026-07-28T09:xx:xx.xxx+08:00"
}
```

所有节点必须遵守：

- `input_data` 保存脱敏摘要，不保存密钥、完整鉴权、完整上传文件。
- `output_data` 保存能解释行为的结构化摘要，长文本使用 preview。
- `duration_ms` 只记录节点内部耗时，不混入上游等待时间。
- `status` 只允许 `success`、`error`、`blocked`、`timeout`、`skipped`。
- `error_message` 只放短错误；结构化错误放入 `output_data.error`。
- `token_usage.usage_source` 只有 `provider` 或 `usage_metadata` 才进入 token 统计；估算值只能用于诊断。

### 2.3 样本链路：`16249051 dev`

样本输入：

```text
request_id=16249051
session_id=playground-1785203315960-jqvgbb
farm_id=2
turn_id=118
user_input=天气咋样
status=success
agent_turn_latency_ms=19042
trace_nodes=mongo:16 mysql:0
messages=mongo:2 mysql:0
```

节点总览：

| 顺序 | 轮次 | 节点 | 耗时 | 作用 |
| --- | --- | --- | --- | --- |
| 1 | r1 | `skill_router.skill_router` | 22ms | 规则命中 `weather.query_forecast`，选择 `weather`。 |
| 2 | r1 | `tool_selection.tool_call_forced` | 1ms | 确认 `tool_choice=auto`，未强制绑定工具。 |
| 3 | r1 | `context_build.context_bundle` | 176ms | 构建 farm、cycle、user_settings、short_term_recent 上下文。 |
| 4 | r1 | `prompt_render.system_prompt` | 1ms | 渲染首轮系统 prompt。 |
| 5 | r1 | `prompt_budget.final_prompt` | 1ms | 预算裁剪后的首轮 prompt 统计。 |
| 6 | r1 | `prompt_budget.final_llm_context` | 1ms | 首轮真实送入 LLM 的上下文快照。 |
| 7 | r1 | `llm_call.Qwen/Qwen3-235B-A22B` | 1093ms | LLM 决定调用 `weather`。 |
| 8 | r1 | `response.final_reply_data_source` | 1ms | 当前还没有工具结果，数据源为 context。 |
| 9 | r1 | `skill_call.weather` | 2425ms | 查询苏州市虎丘区三天天气。 |
| 10 | r2 | `prompt_render.system_prompt` | 4ms | 渲染工具结果回复 prompt。 |
| 11 | r2 | `prompt_budget.final_prompt` | 1ms | 第二轮 prompt 预算统计。 |
| 12 | r2 | `prompt_budget.final_llm_context` | 1ms | 第二轮 LLM 上下文，含工具结果。 |
| 13 | r2 | `reflection_check.pre_final_response` | 0ms | 最终回复前做工具缺失检查。 |
| 14 | r2 | `llm_call.Qwen/Qwen3-235B-A22B` | 5329ms | 生成最终自然语言回复。 |
| 15 | r2 | `response.final_reply_data_source` | 1ms | 数据源改为 `tool:weather`。 |
| 16 | r2 | `agent_response.final_reply` | 0ms | 最终回复落 trace。 |

```json
  "risk": "read",
  "selected": true,
  "why_selected": "混合召回候选 manage_cost.query_summary 排名靠前并被 policy 选中",
  "scores": {
    "final": 0.8231,

    "lexical_hits": ["成本", "多少钱"],
    "low_signal_hits": [],
    "anti_hits": []
  }

```

默认 trace 禁止保存这些重复字段：

| 字段 | 默认处理 | 原因 |
| --- | --- | --- |
| `frames[]` | 不放默认 `output_data`，只放 `debug_raw` | 与 `plan.intent_frames`、`evidence.frames` 重复。 |
| `evidence.frames[]` | 不放默认 `output_data` | 只是 frame 的镜像。 |
| `plan_draft.intent_frames[]` | 压缩为 `plan.steps` | 前端只需要执行计划和校验结果。 |
| 全量 `matched_candidates[]` | 压缩为 `candidate_explanations` | 保留 TopN 和 selected 即可解释选择。 |
| 全量 `scores` 字典 | 合并进 `candidate_explanations[].scores` | 防止一份分数出现多处口径。 |
| 空数组/空对象 | 省略 | 降低 JSON 噪声。 |

### 3.2 `tool_selection.tool_call_forced`

用途：记录 Router 输出如何映射到 LLM 绑定策略。它解释“Router 选了工具，但 LLM 为什么没调用”这类问题。

```json
{
  "node_type": "tool_selection",
  "node_name": "tool_call_forced",
  "input_data": {
    "user_message": "天气咋样"
  },
  "output_data": {
    "selected_tools": ["weather"],
    "forced_skills": [],
    "tool_choice": "auto",
    "bind_tools": ["weather"],
    "reason": "read 工具允许 LLM auto 选择，不强制 tool_call"
  },
  "duration_ms": 1,
  "status": "success"
}
```

字段规则：

- `selected_tools` 来自 Router。
- `bind_tools` 是实际送入 LLM 的工具列表，必须排除 disabled Skill。
- `forced_skills` 只记录需要强制调用的工具。
- 工具结果已返回后，第二轮生成最终回复时应记录 `bind_tools=[]` 或不再产生该节点。

### 3.3 `context_build.context_bundle`

用途：记录本轮选择了哪些上下文块，以及哪些依赖缺失或降级。

```json
{
  "node_type": "context_build",
  "node_name": "context_bundle",
  "input_data": {
    "policy_intent": "query",
    "selected_keys": ["farm", "cycle", "user_settings", "short_term_recent"],
    "block_count": 4
  },
  "output_data": {
    "blocks": [
      {
        "key": "farm",
        "purpose": "农场状态",
        "priority": 90,
        "preview": "农场：管理员农场；称呼：系统管理员；位置：苏州市虎丘区",
        "compressed": false,
        "cache_scope": ""
      },
      {
        "key": "cycle",
        "purpose": "茬口状态",
        "priority": 80,
        "preview": "当前进行中的茬口：夏季西瓜",
        "compressed": false,
        "cache_scope": ""
      }
    ],
    "dependency_diagnostics": {
      "weather_location": {
        "status": "available",
        "source": "farm.location",
        "value_preview": "苏州市虎丘区"
      },
      "weather": {
        "status": "unavailable_but_tool_backed",
        "source": "external_tool",
        "reason": "天气实时数据不在 context 中预取，由 weather skill 查询"
      }
    },
    "allowlist_filtered_keys": ["conversation"]
  },
  "duration_ms": 176,
  "status": "success"
}
```

字段规则：

- `blocks[].preview` 必须裁剪，默认不超过 300 字。
- `dependency_diagnostics.status` 使用枚举：`available`、`missing_required_context`、`unavailable_but_tool_backed`、`skipped_by_policy`。
- 外部实时数据不要在 context build 中伪造，必须标记为 tool-backed。

### 3.4 `prompt_render.system_prompt`

用途：记录使用了哪个 prompt 模板和哪些上下文变量，不用于保存完整不可控 prompt。

```json
{
  "node_type": "prompt_render",
  "node_name": "system_prompt",
  "input_data": {
    "template": "system_base",
    "variables_count": 5,
    "context_blocks": ["farm", "cycle", "user_settings", "short_term_recent"]
  },
  "output_data": {
    "template": "system_base",
    "prompt_preview": "【语言规则】默认使用简体中文回答...",
    "prompt_hash": "sha256:...",
    "prompt_len": 1830
  },
  "duration_ms": 1,
  "status": "success"
}
```

字段规则：

- `prompt_preview` 是调试预览，不超过 2000 字。
- `prompt_hash` 用于判断模板是否变化。
- 第二轮工具结果回复应使用 `template=system_tool_result`。

### 3.5 `prompt_budget.final_prompt`

用途：记录预算裁剪结果，回答“是否因为 token 超预算导致上下文丢失”。

```json
{
  "node_type": "prompt_budget",
  "node_name": "final_prompt",
  "input_data": {
    "system_prompt": true,
    "context_blocks": ["farm", "cycle", "user_settings", "short_term_recent"],
    "messages": 4
  },
  "output_data": {
    "max_tokens": 6000,
    "system_tokens": 739,
    "message_tokens": 76,
    "tool_result_tokens": 0,
    "total_tokens": 815,
    "message_count_before": 4,
    "message_count_after": 4,
    "over_budget": false,
    "actions": [],
    "compression_events": []
  },
  "token_usage": {
    "prompt_tokens": 815,
    "usage_source": "budget_estimate"
  },
  "duration_ms": 1,
  "status": "success"
}
```

字段规则：

- 这是预算估算，不进入费用统计。
- `compression_events` 必须记录被删除或压缩的消息类型、数量和原因。
- `over_budget=true` 时必须有 warning 日志和 trace 节点。

### 3.6 `prompt_budget.final_llm_context`

用途：保存“模型最终看到了什么”的安全快照，是排查幻觉、未调用工具、工具结果没进 prompt 的关键节点。

```json

      {
        "index": 0,
        "role": "user",
        "content_preview": "天气咋样",
        "tool_calls": [],
        "tool_call_id": null
      }
    ],
    "budget": {
      "max_tokens": 6000,
      "total_tokens": 815,
      "over_budget": false
    },
    "compression": {
      "actions": [],
      "events": []
    }
  },
  "token_usage": {
    "prompt_tokens": 815,
    "usage_source": "budget_estimate"
  },
  "duration_ms": 1,
  "status": "success"
}
```

第二轮必须能看见工具结果：

```json
{
  "messages": [
    {
      "index": 4,
      "role": "tool",
      "tool_call_id": "tool-call-weather-1",
      "content_preview": "城市: 苏州市虎丘区\n未来天数: 3天\n当前温度: 31.0℃..."
    }
  ],
  "budget": {
    "tool_result_tokens": 582,
    "total_tokens": 1261
  }
}
```

字段规则：

- 默认展示 role、preview、tool_calls、tool_call_id、预算，不展示完整消息。
- `system_prompt` 在 Mongo 可保留裁剪版；TraceMonitor 列表不展示，只在节点抽屉展示。
- 所有消息 content 必须走脱敏和长度裁剪。

### 3.7 `llm_call.<model>`

用途：记录一次真实 LLM 调用，包括模型、工具绑定、返回形态、token、超时和错误。

首轮工具选择：

```json
{
  "node_type": "llm_call",
  "node_name": "Qwen/Qwen3-235B-A22B",
  "input_data": {
    "input_summary": "天气咋样",
    "provider": "modelscope",
    "model": "Qwen/Qwen3-235B-A22B",
    "role": "generation",
    "selected_tools": ["weather"],
```

### 3.8 `skill_call.<skill>`

用途：记录工具真实执行和权限结果。样本中是 `skill_call.weather`。

```json
{
  "node_type": "skill_call",
  "node_name": "weather",
  "input_data": {
    "operation": "query_forecast",
    "location": "苏州市虎丘区"
  },
  "output_data": {
    "status": "success",
    "legacy_tool_name": "weather",
    "permission_level": "external_network",
    "operation_risk": "external_network",
    "reply_preview": "城市: 苏州市虎丘区\n未来天数: 3天\n当前温度: 31.0℃..."
  },
  "duration_ms": 2425,
  "status": "success"
}
```

失败或拦截：

```json
{
  "node_type": "skill_call",
  "node_name": "manage_cost",
  "input_data": {
    "operation": "create_record",
    "amount": 120,
    "category": "肥料"
  },
  "output_data": {
    "status": "rejected",
    "permission_level": "write",
    "requires_confirmation": true,
    "reason": "写操作需要 pending plan 确认"
  },
  "duration_ms": 0,
  "status": "blocked",
  "error_message": null
}
```

字段规则：

- `input_data` 保存执行参数摘要；敏感字段、长文本和上传文件要裁剪。
- `output_data.reply_preview` 默认不超过 1000 字。
- 写操作未确认时必须是 `blocked` 或 pending，不允许伪装成 `success`。
- 外部网络工具必须标记 `permission_level=external_network` 或等价风险字段。

### 3.9 `response.final_reply_data_source`

用途：标记当前回复会基于什么数据，防止工具查询类问题绕过工具直接回答。

首轮无工具结果：

```json
{
  "node_type": "response",
  "node_name": "final_reply_data_source",
  "input_data": {
    "has_tool_results": false
  },
  "output_data": {
    "data_source": "context_bundle",
    "has_tool_results": false
  },
  "duration_ms": 1,
  "status": "success"
}
```

第二轮已有工具结果：

```json
{
  "node_type": "response",
  "node_name": "final_reply_data_source",
  "input_data": {
    "has_tool_results": true
  },
  "output_data": {
    "data_source": "tool:weather",
    "has_tool_results": true
  },
  "duration_ms": 1,
  "status": "success"
}
```

字段规则：

- 实时数据类回复必须能追到 `tool:<skill>`。
- `context_bundle` 只适合上下文型或闲聊型回答。
- 如果 Router 选择了工具但最终数据源不是工具，应触发诊断 warning。

### 3.10 `reflection_check.pre_final_response`

用途：最终回复前做一致性检查，例如“需要工具但没工具结果”“写操作未确认却声称完成”。

```json
{
  "node_type": "reflection_check",
  "node_name": "pre_final_response",
  "input_data": {
    "farm_id": 2,
    "intent": "query",
    "selected_tools": ["weather"],
    "has_tool_results": true,
    "plan_draft": {
      "route_type": "read_plan",
      "selected_tools": ["weather"]
    }
  },
  "output_data": {
    "checks": ["required_tool_missing"],
    "decision": "pass",
    "issues": [],
    "metadata": {
      "data_source": "tool:weather"
    }
  },
  "duration_ms": 0,
  "status": "success"
}
```

字段规则：

- `checks` 记录启用的检查项。
- `decision` 使用 `pass`、`block`、`repair`。
- `issues[]` 必须包含结构化 `code`、`message`、`severity`。

### 3.11 `agent_response.final_reply`

用途：保存最终用户可见回复摘要和生成原因。

```json
{
  "node_type": "agent_response",
  "node_name": "final_reply",
  "input_data": {
    "message": "天气咋样"
  },
  "output_data": {
    "reason": "react_loop_final_response",
    "reply_preview": "苏州市虎丘区未来三天天气预报：7月28日...",
    "reply_len": 185,
    "skills": ["weather"],
    "data_source": "tool:weather"
  },
  "duration_ms": 0,
  "status": "success"
}
```

字段规则：

- `reply_preview` 默认不超过 1000 字。
- `skills` 来自真实执行结果，不来自 Router 候选。
- `data_source` 必须与最近一次 `response.final_reply_data_source` 对齐。

## 4. 错误节点 JSON 设计

错误不只写字符串，必须同时写可聚合的结构化错误。

```json
{
  "node_type": "skill_call",
  "node_name": "weather",
  "status": "error",
  "duration_ms": 3000,
  "input_data": {
    "operation": "query_forecast",
    "location": "苏州市虎丘区"
  },
  "output_data": {
    "error": {
      "code": "external_weather_timeout",
      "message": "Weather provider timed out",
      "recover": "ask_user_retry_or_use_cached_weather",
      "retryable": true
    }
  },
  "error_message": "Weather provider timed out"
}
```

错误字段规范：

| 字段 | 要求 |
| --- | --- |
| `code` | 必填，稳定枚举，可用于告警和聚合。 |
| `message` | 必填，短描述，不包含密钥和完整 URL。 |
| `recover` | 建议填写，说明自动恢复或人工处理方式。 |
| `retryable` | 外部依赖错误建议填写。 |
| `upstream` | 可选，外部服务名，如 `quillrag`、`weather_provider`、`llm_provider`。 |

## 5. 存储与证据链

| 证据层 | 存储 | 作用 |
| --- | --- | --- |
| 请求摘要 | Mongo `traceRequests` | TraceMonitor 列表、慢请求、根因卡片。 |
| 节点明细 | Mongo `traceRecords` | timeline 和节点抽屉的主事实源。 |
| MySQL 热索引 | `agent_turns` | 通过 `request_id/session_id/turn_id` 定位一轮请求。 |
| MySQL 兼容 trace | `trace_records` | 兼容旧查询；缺表时标记 partial。 |
| 消息证据 | Mongo `conversationMessages` | 用户/助手消息和 `meta.trace_request_id` 回链。 |
| 本地事件 | JSONL `data/agent-events/.../events.jsonl` | append-only 用户/助手事件片段。 |

存储原则：

- Mongo `traceRecords` 是节点级真相源；MySQL trace 缺失不能直接判为链路丢失。
- `traceRequests` 是摘要，不保存完整节点 payload。
- JSONL 路径保存相对路径；读取时按后端 cwd、项目根、`backend/` 三个锚点解析。
- `conversationMessages.meta.trace_request_id` 是从消息反查 trace 的主键。
- `agent_turns.event_file + event_seq_start/event_seq_end` 是读取 JSONL 片段的首选入口。

## 6. 裁剪、脱敏与 Debug 展开

默认 trace 要可读、可聚合、可长期保存。完整证据只在节点详情或 `debug=true` 时展开。

裁剪规则：

```json
{
  "__trace_truncated": true,
  "__trace_original_json_len": 238912,
  "__trace_truncate_reason": "payload_exceeds_128kb",
  "preview": "裁剪后的摘要..."
}
```

必须脱敏的 key：

- `password`
- `token`
- `api_key`
- `authorization`
- `cookie`
- `secret`
- `credential`
- `base_url` 中带账号密码的部分

Debug 展开规则：

- 默认列表只展示 `summary`、`metrics`、`root_error`、节点名称、耗时和状态。
- 节点抽屉展示该节点 `input_data/output_data/token_usage/error_message`。
- `debug=true` 可返回 `debug_raw`，但仍必须经过脱敏和结构化裁剪。
- `app.log` 不输出完整 JSON，只输出短摘要或多行人读 trace。

## 7. 日志与 Trace 边界

日志用于实时观察，trace 用于事后诊断。

日志应该像这样短：

```text
event=skill_router_completed request_id=16249051 status=success duration_ms=22 selected_tools=weather selection_path=rule_classifier retrieval_engine=rule_intent_classifier rag_service_used=false embedding_location=none
```

人读多行日志可以辅助本地调试：

```text
event=skill_router_trace
Skill Router Trace
  route: path=rule_classifier engine=rule_intent_classifier duration_ms=22 candidates=13
  recall: skipped
    reason: rule_classifier_matched
    meaning: 规则分类器已命中，跳过 BM25 + RAG 向量召回
    external_rag_call: no
    embedding_call: no
  selected: routes=weather.query_forecast tools=weather
```

但机器可读事实必须来自：

- `traceRecords.output_data.recall`
- `traceRecords.output_data.candidate_explanations`
- `traceRequests.metrics`
- `agent_turns`
- `conversationMessages.meta`

禁止：

- 把完整候选 JSON 压成一行写进 `app.log`。
- 只写 `duration_ms`，不写调用了哪个外部服务。
- 用 `bm25=no vector=no` 这类不解释含义的字段替代 `recall.status + meaning`。

## 9. 指标与告警

从 trace 聚合以下指标：

| 指标 | 来源 | 用途 |
| --- | --- | --- |
| `agent_turn_latency_ms` | `agent_turns.latency_ms` | 总耗时告警。 |
| `node_duration_sum_ms` | `traceRecords.duration_ms` | 判断埋点覆盖。 |
| `unattributed_duration_ms` | request summary | 发现 SSE、持久化或未埋点耗时。 |
| `llm_call_timeout_count` | `llm_call.status=timeout` | LLM provider 健康度。 |
| `skill_call_error_count` | `skill_call.status=error` | Skill 稳定性。 |
| `router_fallback_count` | `skill_router.output_data.summary.fallback` | Router 命中质量。 |
| `rag_recall_count` | `skill_router.output_data.recall.rag_service_used` | QuillRAG 调用量。 |
| `local_doc_embedding_calls` | `skill_router.output_data.recall.local_doc_embedding_calls` | 防止在线重复生成 Skill embedding。 |

默认告警：

- 单轮总耗时超过 15 秒。
- 单个 LLM 节点超过 8 秒。
- 单个外部工具超过 5 秒。
- `local_doc_embedding_calls > 0`。
- Router fallback 率超过 10%。
- `unattributed_duration_ms` 连续超过 5 秒。

## 10. 落地清单

1. `skill_router.skill_router` 默认 payload 改为 `summary + selected + recall + candidate_explanations + plan`。
2. Admin Skill 检索测试展示完整 Router JSON 时，明确区分 `default_trace` 与 `debug_raw`。
